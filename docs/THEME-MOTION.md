## Motion profiles

| Mode      | Module entrance                                                | Response                                                                                                                           |
| --------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Editorial | 12px travel, 600ms settling ease, up to 65ms between modules   | Project titles move 3px; images scale to 1.015; existing link underlines remain single                                             |
| Engineer  | 6px travel, 240ms precise ease, up to 35ms between modules     | Records gain an accent perimeter; navigation responds without card travel. No left inset rail or capability hover border           |
| Digital   | 22px travel, 700ms expressive ease, up to 90ms between modules | Images scale to 1.025, capability panels lift, the portal tilts up to 3 degrees, and monochrome border glimmers follow hover/focus |

Entrance staggering is capped at three increments. Digital's decorative orbit settles
once over 1200ms. There is no recurring ambient loop. Mobile menus and mode pickers
have short opening transitions, indicator rotation and press feedback. Technical
disclosures retain native details/summary behavior with enhanced opening motion.

### Border refinement

Tyler requested removal of Engineer's left project inset rail and green capability
hover border. Native link focus outlines and the project perimeter response remain.

Digital project cards, capability panels and the hero portal now have a monochrome
edge glimmer inspired by the rotating-edge examples in
[How to Animate Borders in CSS](https://www.letsbuildui.dev/articles/how-to-animate-borders-in-css/).
A masked conic-gradient pseudo-element preserves the translucent inner surface;
an interpolated angle moves the glimmer around the perimeter every three seconds.
Projects use their existing status accent and other panels use cyan. It runs only
during fine-pointer hover or keyboard focus, does not intercept clicks, and stops
when neither state applies. Reduced motion retains a static edge highlight.

## Architecture and continuity

`src/lib/motion/page-motion.ts` observes semantic module identities and
`data-motion-reveal` boundaries. `data-motion-group` permits child modules to
enter independently without also moving their parent. Facts and content schemas
do not know which motion profile is active.

The implementation uses [Intersection Observer](https://www.w3.org/TR/intersection-observer/)
and [Web Animations](https://www.w3.org/TR/web-animations-1/) with CSS for interaction
states. Modules reveal once per mounted route. Their entrance changes translation,
not opacity: content is readable before hydration and remains readable if the
observer or animation APIs are unavailable. No animation package was added.

Theme changes cancel entrance and pointer motion before snapshot capture. The new
composition's visible modules skip entry replay; below-fold modules can still
reveal when reached. Route and preview-query changes dispose observers, pointer
listeners and animations before registering the new content. Keyboard focus
settles any moving ancestor so the focused target is stable.

Portal pointer updates use at most one pending animation frame, and stop when the
pointer leaves. No React state updates run per frame. This enhancement is installed
only for Digital portals, and requires a mouse with a fine pointer and hover support.
Keyboard users receive static focus/glow feedback; touch input keeps ordinary
navigation and press states.

## Reduced motion and native behavior

OS reduced motion disables expressive entrance, tilt, scale, travel and menu
opening animations. Changing the preference during motion cancels active animations
and clears pointer offsets. Development previews provide the same static treatment
through their reduced-motion control. Color, borders and focus remain useful state
feedback.

Menu entrance animation requires the client enhancement marker. JavaScript-disabled
menus and theme forms keep native behavior and static content. No scrolling is
intercepted, and essential information is never restricted to hover.

Individual transform resets are deliberately separated from the transform shorthand:
the CSS compiler otherwise optimizes away scale/translate resets that must override
scoped interaction rules. Populated preview tests cover the compiled result.
