## 2. Project identity and scope

**Name / slug:** Nihonest / `nihonest`. **Candidate period:** 2026 (repository history only). **Category:** public information web application with a local editorial tool. **Actual state:** active local implementation before first public deployment; neither a verified production application nor only a mockup (`README.md:27-29`, `docs/ROADMAP.md:992-1010`). **Audience:** people preparing to move to, study, work, or live in Japan (`docs/PRODUCT.md:33-61`). **Purpose/problem:** make official processes and Japanese administrative terminology easier to navigate while linking to responsible authorities; the project explicitly avoids individualized legal determinations (`docs/PRODUCT.md:5-26`).

**One sentence:** Nihonest is a public-first, source-linked guide to moving to and living in Japan, with optional route-aware journeys and account features. **Short description:** Its English canonical content is assembled from MDX articles and typed records, then exposed through search, structured discovery, journeys, glossary, FAQ, residence-status guidance, and municipality-specific supplements. A separate loopback CMS assists editorial review without publishing (`src/lib/content/articles.ts:35-83`, `src/lib/search/knowledgebase-search.ts:39-69`, `tools/cms/README.md:1-7`).

**Implemented in the checkout:** public pages and discovery (`src/app/page.tsx:27-63`, `src/app/explore/page.tsx`, `src/app/faq/page.tsx`, `src/app/glossary/page.tsx`); typed, cross-validated content and citations (`src/lib/content/articles.ts:42-79`); 20 named guided journeys and route/conditional-step resolution (`src/data/discovery.ts:14-35`, `src/domain/discovery/discovery.ts:7-42,75-85`); locally stored preferences and progress (`src/lib/storage/anonymous-preferences.ts:8-18`, `src/components/roadmap/personalized-roadmap.tsx:50-60`); a local Supabase optional-account and sync layer (`src/lib/sync/account-content-sync.ts:10-31`, `supabase/migrations/20260907000100_create_account_foundation.sql:12-70`); municipality guidance with explicit researched versus general fallback (`src/components/local-guidance/local-guidance-panel.tsx:82-91,194-229`); English/Japanese catalog overlays and English fallback, with machine-translation status (`src/lib/translation/translation-service.ts:36-94`, `content/translations/CLAUDE-TRANSLATION-REPORT.md:3`); and a single-editor local CMS (`tools/cms/README.md:1-72`). ## 4. Technology and architecture

**Material stack:** Next.js 16.3.4, React 19.2.4, TypeScript, MDX, Zod, Tailwind CSS 4, Supabase SSR/client and PostgreSQL migrations, Vitest/Testing Library, Playwright, ESLint (`package.json:6-79`). Node 24 is the declared runtime line (`package.json:5-7`). AWS SES is present as a provider implementation, but operational delivery is not established (`src/lib/notifications/amazon-ses-email-provider.ts`, `docs/ROADMAP.md:992-1009`). Avoid listing React Native/Expo as implemented.

**Flow:** canonical English MDX and typed `src/data` registries → `src/lib/content/articles.ts` parses and cross-validates IDs, sources, glossary, journeys, local guidance, and documents → `src/app` renders public routes, while `src/lib/search` builds an in-memory index for group/FAQ/article/glossary discovery (`src/lib/content/articles.ts:35-83`, `src/lib/search/knowledgebase-search.ts:39-69,128-142`). `src/domain` holds schemas and portable rules; `npm run architecture:check` enforces import and cycle boundaries (`docs/ARCHITECTURE.md:95-118`, `scripts/check-architecture.ts`). Anonymous device state lives in browser storage; an optional signed-in account passes a validated snapshot to the `sync_account_content` database function, whose user tables carry RLS owner policies (`src/lib/sync/account-content-sync.ts:10-31`, `supabase/migrations/20260908000100_create_account_content_sync.sql:1-57`). The local CMS edits canonical repository files; its guards require expected revisions, a clean starting file, server-side validation, and a local origin/session token; it is outside `src/` (`tools/cms/README.md:30-41,62-72`). Japanese overlays are revision-addressed derivatives, not a separate canonical content set (`src/lib/translation/translation-service.ts:36-94`).

**Useful diagram:** `architecture-content-boundaries` in `diagrams/architecture-content-boundaries.json` in the bundle. Accessible summary: repository content is validated before rendering public pages; browser preferences remain local until an optional account syncs selected state through Supabase; the local CMS edits repository content but is not a public route. This is a checkout architecture, not a deployed topology.
